## 0. 콘텐츠 UX 스프린트 (이번 회차)

기능이 아니라 **설명하는 말**을 고친 회차다. 판단의 출발점은 이거였다.

> 현재 교육 카피는 `이게 뭐예요?`에는 답하지만,
> 우리 사용자가 실제로 가진 `이거 대충 아는데 그래서 어떻게 읽는 거였지?`에는
> 답하지 못한다.

동의한다. 그리고 화면을 뜯어 보니 원인 하나는 **콘텐츠가 아니라 코드**였다.

### 0.1 가장 큰 원인은 해설 선택 순서였다

디스인플레이션을 맞힌 뒤 나온 해설이 `디플레이션과 바꿔 쓰지 않아요`뿐이었던 것은
원고가 없어서가 아니다. `src/lib/quiz.ts`의 `explanationNote`가 후보를 이 순서로
골랐기 때문이다.

```
commonConfusions[0] → whyItMatters → easyExplanation → keyPoints[0]
```

혼동 경고가 1순위였다. 그런데 `whyItMatters`에는 이미 `그래서 어떻게 읽는지`가
들어 있는 경우가 많았다. 즉 좋은 문장을 써 두고 화면에는 경고를 보여 주고 있었다.

순서를 뒤집고 2단계 구조를 코드로 못박았다.

```
① 이게 뭔지        — 문항이 이미 말했으므로 해설에서 생략
② 그래서 어떻게 읽는지 — whyItMatters
③ 혼동 가능성이 높을 때만 차이 — commonConfusions
```

③은 ②가 한 문장일 때만 붙인다. ②가 이미 두 문장이면 붙이지 않는다.
5분 세션에서 해설이 세 문장을 넘으면 안 읽는다.
또 낱말 겹침(`saysSame`)으로 같은 말을 두 번 하지 않게 막았다.
앞부분만 비교하던 예전 방식은 `커졌다고 가계가 모두 넉넉해졌다는 뜻은 아니에요`와
`GDP가 늘었다고 가계가 모두 부유해진 것은 아니에요`를 다른 문장으로 통과시켰다.

결과: 해설 100개 평균 70자, 최장 102자, 빈 해설 0개.
`npm run review-copy`로 전수 확인한다.

### 0.2 정의를 다시 말하는 원고 48개를 걷어냈다

`whyItMatters`의 첫 문장이 `oneLiner`를 되풀이하는 것이 48개였다
(글자 그대로 겹치는 23개 + 표현만 바꿔 겹치는 25개).
문항이 정의를 말한 직후에 해설이 또 정의를 말하면 얻는 게 없다.

전부 첫 문장을 떼고, 홀로 서지 못하는 문장은 손으로 다시 썼다.
검사기가 이제 어휘 겹침 34% 이상이면 실패시킨다.

특히 GPT가 짚은 것들:

| 용어 | 전 | 후 |
| --- | --- | --- |
| 디스인플레이션 | 디플레이션과 바꿔 쓰지 않아요 | 기사에서 물가 상승세가 둔화됐다고 해도 가격이 내려갔다는 뜻은 아니에요. 상승률이 4%에서 2%로 낮아져도 물건 값은 여전히 오르는 중일 수 있어요 |
| 잠재GDP성장률 | 잠재성장률이 높다고 **올해 실적이** 좋다는 뜻은 아니에요 | 잠재성장률이 높다고 올해 경제가 실제로 그만큼 성장했다는 뜻은 아니에요. 실제 성장률과는 다른 숫자예요 |
| 경기 | 한 지표만으로 좋다·나쁘다를 단정하지 않아요 | 기사에서 경기가 꺾였다고 할 때는 어떤 지표를 근거로 삼았는지 보면 판단이 달라져요 |
| 지급준비제도 | 비율이 오르면 대출로 나갈 돈이 줄어들어요 | (앞과 같고) 다만 대출이 그 비율만큼 기계적으로 줄어드는 것은 아니라서, 다른 정책 수단과 함께 봐야 해요 |
| 최종대부자기능 | 누가, 어떤 담보로 공급하는지가 핵심이에요 | 위기 때 중앙은행이 나섰다는 기사를 읽을 때는 어디에 어떤 담보를 받고 공급했는지를 보면 성격이 갈려요 |

`실적`은 반드시 고쳐야 했다. 기업 실적으로 읽힌다.

### 0.3 문체를 해요체로 통일했다 (1,390곳)

`scripts/to_haeyo.py`로 옮겼다. 규칙 + 예외 사전 두 층이다.
한글 활용은 규칙만으로 안 된다. 실제로 규칙만 돌렸을 때 이런 오변환이 나왔다.

| 잘못 | 바로잡음 | 왜 |
| --- | --- | --- |
| 보입니다 → 보예요 | 보여요 | 명사 + 이다가 아니라 동사 보이다 |
| 다릅니다 → 다러요 | 달라요 | 르불규칙 |
| 만듭니다 → 만드어요 | 만들어요 | ㄹ탈락을 되돌려야 함 |
| 가깝습니다 → 가깝아요 | 가까워요 | ㅂ불규칙 |
| 나타냅니다 → 나타내어요 | 나타내요 | ㅐ + 어 축약 |
| 찼습니다 → 찼아요 | 찼어요 | 과거형 판정 누락 |

375종 변환표를 전부 눈으로 확인한 뒤 적용했다.
**한국은행 원문 787개는 건드리지 않았다.** 원문은 `public/data/terms.json`에 있고
이 스크립트는 `src/content/*.ts`만 본다. 공식 정의를 우리 말투로 고치면 원문이
아니게 된다.

검사기가 이제 우리 원고 9개 파일에서 `-니다` 어미를 하나라도 찾으면 실패한다.

### 0.4 오답을 유사개념 중심으로 바꿨다

화면에서 실제로 이랬다.

> 노동과 자본을 무리 없이 썼을 때 유지될 수 있는 성장 속도는?
> 청년실업률 / 경기조절정책 / 연구개발 / **잠재GDP성장률**

성장 속도를 묻는데 나머지가 실업률, 정책, 연구개발이다. 학습이 아니라 소거법이다.
원인은 오답을 **같은 분야**에서만 뽑았기 때문이다. `경기·성장` 분야에는
잠재GDP성장률과 연구개발이 함께 들어 있다.

세 가지를 했다.

1. **종류 일치**: 표제어 끝으로 종류를 가른다(`~성장률`, `~제도`, `~지수`, `~금리`…).
   성장률에는 다른 성장률을 놓는다.
2. **말토막 공유**: 이름이 두 글자 이상 겹치면 우선한다.
   광의통화↔협의통화, 고정환율제도↔변동환율제도처럼 이름으로 지울 수 없게 만든다.
3. **핵심 100개는 손으로 지정**: CONTRAST 항목을 29개 → 100개로 늘렸다.
   Core100 전부가 이제 사람이 검수한 오답을 갖는다.

| | 전 | 후 |
| --- | --- | --- |
| 사람이 지정 | 29개 | **100개 (핵심 전부)** |
| 자동 생성이 기준 통과 | 22% | 43% |
| 헷갈릴 만한 오답을 가진 용어 | 29/194 (15%) | **141/194 (72%)** |

부수 효과로 `헷갈리는 개념 구분하기` 문항을 지원하는 핵심 용어도 29개 → 100개가 됐다.
지난 회차 보고서의 커버리지 공백이 여기서 닫혔다.

GPT가 준 예시는 그대로 반영했다.

```
지급준비제도  : 예금보험제도 / 공개시장운영 / BIS자기자본비율
듀레이션      : 만기수익률 / 표면금리 / 신용스프레드
기대인플레이션 : 소비자물가지수 / 근원인플레이션율 / 물가안정목표제
잠재GDP성장률 : 경제성장률 / GDP갭 / 국내총생산
```

### 0.5 화살표를 검수된 흐름에만 쓴다

이 지적이 이번 피드백에서 가장 중요했다. 화면에 이렇게 나가고 있었다.

```
잠재GDP성장률 → GDP갭 → 물가 → 기준금리
```

**GDP갭은 잠재성장률이 일으키는 게 아니다.** 실제 GDP와 잠재 GDP의 **차이**다.
정의 관계를 인과처럼 가르치면 사용자가 잘못 배운다.
`지급준비금 → 대출`도 기계적 인과가 아니다.

두 종류로 나눴다.

- **`이렇게 이어서 볼 수 있어요`** — `src/content/conceptFlows.ts`에 적은 12개만.
  화살표를 쓰고, **관계가 무엇인지 한 문장으로 함께 적는다.** 화살표만 두면
  사용자가 알아서 인과로 읽기 때문이다.
- **`같이 보면 좋은 개념`** — 나머지 관련 용어. 칩으로만 보여 준다.
  확인하지 않은 인과를 화살표로 씌우지 않는다.

검사기가 흐름마다 칸 3개 이상과 관계 설명 40자 이상을 요구한다.

### 0.6 오답을 골랐을 때 차이를 보여 준다

`틀렸어요`나 정답 설명만으로는, 자기가 왜 그걸 골랐는지가 그대로 남는다.
우리 사용자는 두 개념을 맞바꿔 알고 있는 상태다.

이제 이렇게 나간다.

```
정답은 기대인플레이션이에요
인플레이션은 물건 값이 전반적으로, 그리고 계속 오르는 현상이에요.
여기서 물어본 것은 기대인플레이션이에요.
```

`differenceNote`가 고른 보기의 `oneLiner`를 써서 만든다. 새 엔진은 없다.
조사(`은/는`, `이에요/예요`)는 받침을 보고 고른다.

### 0.7 화면 문구

| 위치 | 전 | 후 |
| --- | --- | --- |
| 홈 | `오늘 이만큼만 하면 충분합니다` + 큰 `7분` 두 줄 | **`오늘은 7분이면 돼요`** 한 줄 + `새 용어 2개 · 복습 4개` |
| 홈 | `익힐 개념` | **`새로 볼 용어`** |
| 홈 | `개념 연결해서 보기` | **`개념 흐름 보기`** |
| 홈 | `학습 가능한 용어 221개 · 아직 안 본 용어 215개` | **삭제.** `지금까지 본 용어 N개 · 익숙해진 용어 N개` |
| 세션 제목 | `방금 본 용어 3/8` → `복습 5/8` (기준이 중간에 바뀜) | **`오늘 학습 3/8`** 로 통일 |
| 문제 유형 | 뜻 고르기 / 용어 떠올리기 / 비슷한 개념 구분 / 맞는 설명인지 판단 / 짧은 상황에 적용 | **뜻 맞히기 / 설명 보고 맞히기 / 헷갈리는 개념 구분하기 / 맞을까? / 문장에서 찾기** |
| 복습 예정 | `다음 복습은 2일 뒤입니다` | **`2일 뒤에 다시 나와요`** |

`221개`를 지운 이유는 그게 시스템 언어이기 때문이다.
`한국은행 용어가 787개라는데 왜 221개지`라는 의문만 새로 만들고,
`215개 남음`은 우리가 원하지 않는 완주 압박을 준다.

### 0.8 정답 상태를 색상 외에 글로 적는다

초록·빨강 테두리만으로 판정하지 않는다. `✓ 맞았어요` / `정답은 듀레이션이에요`를
`role="status"`로 적는다. 접근성뿐 아니라 `그래서 정답이 뭐였지`가 안 남는다.

답을 고른 뒤 나머지 보기는 높이와 글자를 줄여(`\.choice.dim`) 해설을 위로 끌어올렸다.

### 0.9 신규 용어 하나를 오늘 읽기에 연결했다

전에는 신규 둘 다 분야 순환으로만 뽑았다. 그래서 읽기가 물가 이야기인 날에
디스인플레이션과 지급준비제도가 함께 나왔다. 세션을 마치고 `오늘 뭘 배운 거지`가 된다.

이제 하나는 오늘 읽기에 걸린 개념에서 뽑고(`LEARNING_MAPS.readingId`),
나머지는 기존 분야 순환으로 뽑는다. 구조와 다양성 중 하나를 버리지 않는다.
홈과 학습 화면이 같은 읽기 id를 넘기게 고쳐 두 화면의 신규 용어가 어긋나지 않는다.

### 0.10 받아들이지 않은 것

**토스식 단순화.** `PER이 낮을수록 저평가`는 이해하기 쉽지만 금융적으로 틀렸다.
성장률·위험·일회성 이익·업종 차이 때문에 낮을 수도 있다.
그래서 설명 **방식**만 가져오고 단정은 가져오지 않았다. 우리 PBR 해설은 이렇게 썼다.

> 1배 아래라고 곧 저평가라고 보기는 어려워요. 자산의 실제 가치나 수익성이
> 장부만큼 못 되는 경우에도 낮게 나오기 때문에 자기자본이익률을 같이 봐요.

**UI 전면 개편.** 하지 않았다. dark theme, spacing, touch target, CTA 위계는
그대로 두고 내용의 밀도와 위계만 손봤다. 여기는 GPT 판단에 동의한다.

## 1. 지난 회차에 확정한 것

### 알림·브랜드 문구 (제품 결정, 코드가 조건을 지킨다)

`src/content/notifications.ts` 한 곳에만 있다. 클라이언트와 크론이 같은 함수를 쓴다.

| 상황 | 제목 | 본문 |
| --- | --- | --- |
| 오늘 미완료 | 5개 문구를 날짜로 돌려 쓴다. 예: `오늘도 금맹 탈출을 위해 파이팅!` | `딱 5분이면 오늘 몫은 끝나요.` |
| **2~3일 이탈** | **`금융문맹 되어가는 중…`** | `오늘 5분만 다시 해볼까요?` |
| 4~6일 이탈 | `슬슬 다시 해볼까요?` | `오늘도 5분이면 충분해요.` |
| 7일 이상 | `오랜만이에요.` | `오늘 5분만 다시 시작해볼까요?` |
| 3일 연속 | `🔥 N일 연속. 이 정도면 금맹탈출할 듯.` | `오늘 것도 5분이면 끝나요.` |

바뀐 점 둘.

- 브랜드 문구 구간을 2~6일에서 **2~3일**로 좁혔다. 4~6일은 별도 문구다.
  이전에 6일까지 넓힌 것은 합의 범위를 벗어난 임의 확대였다.
- `오늘 공부할 게 남아 있어요`를 버렸다. 사실이지만 퇴근길에 받으면 할 일이 하나
  늘어난 것으로 읽힌다. 남은 분량을 알리는 대신 같이 해보자고 말한다.
  이 톤 원칙은 `scripts/test-nudge.mjs`가 독촉 표현 목록으로 검사한다.

조건은 코드로 못박았고 17건이 검사한다.
학습 이력이 없으면 아무 문구도 안 나가고(첫 사용자에게 `오랜만이에요`가 뜨던 버그),
같은 공백 구간에서 같은 문구를 두 번 보내지 않고, 하루 1회를 넘지 않는다.
온보딩과 문제 화면에는 브랜드 문구를 쓰지 않는다.

**숫자 강제 규칙을 제거했다.** `숫자 없으면 실패`는 잘못된 규칙이었다. 그렇게 쓰면
숫자가 없어도 자연스러운 글에 억지로 숫자를 밀어넣게 된다. 대신 세 가지를 본다.

1. 변화·대조·원인·해석 신호가 둘 이상 있는가 (읽을 거리인지)
2. 숫자를 썼다면 단위가 붙어 있는가
3. 실제 규제 수치처럼 읽힐 표현을 쓰지 않았는가

이 새 규칙이 실제로 약한 글 3편(`cx-bankrun`, `cx-dsr`, `cx-defi-cbdc`)을 잡아냈다.
사건만 나열되고 해석이 없었다. 해석 문장을 붙였다.

**오해 위험 수치를 고쳤다.**

- `cx-ltv`: `상한 70% → 50%`는 실제 한국 LTV 규제 수치와 거의 같아 현행 제도로
  읽힐 수 있었다. `상한 10%포인트 하락 / 대출 1억 원 감소`로 바꿨다.
- `cx-unemployment`: `3.7% → 4.1%`는 실제 발표처럼 보이는 정밀도였다.
  `3%대 후반 → 4%대 초반`으로 바꿨다.
- 읽기 화면 본문 아래에 `숫자도 설명을 위해 만든 값입니다`를 명시했다.

남긴 수치: `cx-core-cpi`의 `3.1% → 2.4%` / `2.9% → 2.8%`.
헤드라인은 내리는데 근원은 제자리라는 대조가 이 글의 전부이므로 숫자가 교육적으로
필요하다. 사람 검수에서 유지 여부를 최종 판단한다.

읽는 법: **세션 시간은 정답률과 거의 무관하다.** 개수가 아니라 시간 예산으로 뽑기
때문이다. 대신 진도가 느려진다. 이건 옳은 교환이다. 틀리는 사람에게 시간을 더
요구하는 대신 덜 나아간다.

찾은 결함: 정답률 60%에서 네 번 이상 틀린 카드가 매일 되돌아와 신규 학습이 거의
멈췄다(시작 용어 37개 대 기준선 60개). 사용자 체감은 `모르는 것만 계속 나온다`다.
`relearnInterval`을 넣어 세 번째 실패부터 이틀, 다섯 번째부터 사흘을 두게 했다.
큐에서 빼지는 않는다. 어려운 카드를 숨기는 게 아니라 다른 것을 볼 자리를 남긴다.
결과: 시작 용어 37 → 39개, B유형 30일차 밀림 6 → 0개. 전부 정답 기준선은 불변.

### 서버 방어

| 항목 | 처리 |
| --- | --- |
| `/api/export` | 토큰 없으면 404. **비밀값 미설정 시 통과가 아니라 거부.** 길이 16자 미만도 거부 |
| `/api/cron-nudge` | 같은 규칙 + Vercel 크론 헤더 허용 |
| `/api/events` | learnerId 형식 검사, 이벤트 200개·본문 128KB·payload 키 20개·문자열 200자 상한, IP당 분당 30회 |
| `/api/daily-status` | learnerId 형식 검사, 구독 정보 형태 검사(https·길이), 분당 30회 |
| 비밀값 노출 | `VITE_` 접두사만 번들에 들어간다. Upstash 토큰과 VAPID private key는 서버 전용 |
| 만료 구독 | 404/410 응답이면 구독을 지운다 |
| 검색 노출 | 관리 엔드포인트에 `X-Robots-Tag: noindex` |

`/api/health`를 만들었다. 원칙은 **사용자에게는 조용히 degrade, 운영자에게는 시끄럽게
실패**다. `/api/events`는 설정이 없어도 200을 주지만, `/api/health`는 하나라도
빠지면 503과 함께 누락 목록을 준다. 파일럿 시작 전 이 응답이 200인지 확인한다.

이전 구현의 구멍: `if (secret && auth !== ...)`로 써서 **환경변수를 잊으면
`/api/export`가 그대로 열렸다.** 잊어버리는 쪽이 안전한 방향이어야 한다.

### 이벤트 중복과 스키마

`eventId`(UUID)와 `eventSchemaVersion`을 넣었다. 전송 실패 시 커서를 올리지 않고
다시 보내므로 같은 이벤트가 두 번 닿을 수 있다. 집계 때 `eventId`로 걸러낸다.
CSV에도 두 열이 나온다.

### 완료 상태 유실 → 잘못된 알림

지적한 엣지 케이스가 실제 위험이었다. 이벤트 몇 개 유실은 괜찮지만 완료 사실이
서버에 닿지 않으면 그날 저녁에 다 한 사람에게 독촉이 간다. 그래서 두 경로의 신뢰도를
다르게 뒀다.

- 이벤트: 실패하면 커서만 유지. 다음에 같이 보낸다.
- 완료 상태: 실패하면 **outbox에 남긴다.** 앱을 다시 열 때, 화면이 다시 보일 때,
  온라인으로 돌아올 때 재전송한다(`src/main.tsx`).

### 기록 지우기와 서버 상태 일치

`기록 지우기`가 이제 네 가지를 함께 한다: 알림 구독 해지 → 서버 기록 삭제 →
**익명 id 새로 발급** → 기기 데이터 삭제. 지운 시점 이전과 이후는 다른 사람으로 센다.

### 문구 정리

- 온보딩: `들어본 말은 많은데, 막상 설명하려면 헷갈린다면.`
- 추가 세션의 `지금 더 풀어도 다음 복습은 예정대로 나와요`를 **삭제**했다.
  사용자는 복습 일정이 앞당겨지는지를 애초에 궁금해하지 않는다. 내부 동작을 설명하려고
  화면에 줄을 하나 더 두지 않는다. 동작 자체는 그대로다.

지난 회차 대비 콘텐츠 품질이 크게 움직였다.

| | 지난 회차 | 이번 회차 |
| --- | --- | --- |
| 문체 | `-습니다` 1,390곳 | 해요체 통일, 검사기가 지킨다 |
| 정답 후 해설 | 혼동 경고 1순위 | 해석 1순위, 2단계 강제, 평균 70자 |
| 정의 되풀이 | 48개 | 0개 (검사기가 막는다) |
| 헷갈릴 만한 오답 | 15% | 72% |
| 검수한 화살표 흐름 | 0개 (전부 자동) | 12개, 나머지는 칩 |
| 오답 시 차이 설명 | 없음 | 있음 |
| 정답 상태 표시 | 색상만 | 색상 + 글 |

**여기서 필요한 것은 코드가 아니라 병욱님이 화면을 넘겨 보는 일이다.**
자동 검사는 `정의를 되풀이하지 않는가`까지 잡아낸다. 잡지 못하는 것은
`이 문장을 읽고 실제로 기사를 읽을 수 있게 되는가`다. 그건 사람만 판단한다.

가장 짧은 경로:

1. `npm run review-copy`로 해설 100개를 훑는다. 약한 것에 표시만 해 준다.
2. 배포된 앱에서 세션을 3~4일치 해 본다. 특히 틀렸을 때의 차이 설명과 개념 흐름.
3. `python3 scripts/to_haeyo.py --check`로 어색한 어미를 찾는다.

이 셋이 끝나면 남는 것은 서버 환경 변수와 기기 확인뿐이다.
