## 1. 이번에 확정한 것

### 알림·브랜드 문구 (제품 결정, 코드가 조건을 지킨다)

`src/content/notifications.ts` 한 곳에만 있다. 클라이언트와 크론이 같은 함수를 쓴다.

| 상황 | 제목 | 본문 |
| --- | --- | --- |
| 오늘 미완료 | 5개 문구를 날짜로 돌려 쓴다. 예: `오늘도 금맹 탈출을 위해 파이팅!` | `딱 5분이면 오늘 몫은 끝나요.` |
| **2~3일 이탈** | **`금융문맹 되어가는 중…`** | `오늘 5분만 다시 해볼까요?` |
| 4~6일 이탈 | `슬슬 다시 해볼까요?` | `오늘도 5분이면 충분해요.` |
| 7일 이상 | `오랜만이에요.` | `오늘 5분만 다시 시작해볼까요?` |
| 3일 연속 | `🔥 N일 연속. 이 정도면 금맹탈출할 듯.` | `오늘 것도 5분이면 끝나요.` |

바뀐 점 둘.

- 브랜드 문구 구간을 2~6일에서 **2~3일**로 좁혔다. 4~6일은 별도 문구다.
  이전에 6일까지 넓힌 것은 합의 범위를 벗어난 임의 확대였다.
- `오늘 공부할 게 남아 있어요`를 버렸다. 사실이지만 퇴근길에 받으면 할 일이 하나
  늘어난 것으로 읽힌다. 남은 분량을 알리는 대신 같이 해보자고 말한다.
  이 톤 원칙은 `scripts/test-nudge.mjs`가 독촉 표현 목록으로 검사한다.

조건은 코드로 못박았고 17건이 검사한다.
학습 이력이 없으면 아무 문구도 안 나가고(첫 사용자에게 `오랜만이에요`가 뜨던 버그),
같은 공백 구간에서 같은 문구를 두 번 보내지 않고, 하루 1회를 넘지 않는다.
온보딩과 문제 화면에는 브랜드 문구를 쓰지 않는다.

### 읽기 32편

| | 전 | 후 |
| --- | --- | --- |
| 본문 길이 | 38~105자 (평균 65자) | 181~249자 (평균 214자) |
| 문장 수 | 1~2문장 | 4~6문장 |
| 두 배 이상 확장 | | 31/32편 |
| 읽기 방식 | 없음 | 이름 12 / 원인 11 / 다음 확인 9 |

**숫자 강제 규칙을 제거했다.** `숫자 없으면 실패`는 잘못된 규칙이었다. 그렇게 쓰면
숫자가 없어도 자연스러운 글에 억지로 숫자를 밀어넣게 된다. 대신 세 가지를 본다.

1. 변화·대조·원인·해석 신호가 둘 이상 있는가 (읽을 거리인지)
2. 숫자를 썼다면 단위가 붙어 있는가
3. 실제 규제 수치처럼 읽힐 표현을 쓰지 않았는가

이 새 규칙이 실제로 약한 글 3편(`cx-bankrun`, `cx-dsr`, `cx-defi-cbdc`)을 잡아냈다.
사건만 나열되고 해석이 없었다. 해석 문장을 붙였다.

**오해 위험 수치를 고쳤다.**

- `cx-ltv`: `상한 70% → 50%`는 실제 한국 LTV 규제 수치와 거의 같아 현행 제도로
  읽힐 수 있었다. `상한 10%포인트 하락 / 대출 1억 원 감소`로 바꿨다.
- `cx-unemployment`: `3.7% → 4.1%`는 실제 발표처럼 보이는 정밀도였다.
  `3%대 후반 → 4%대 초반`으로 바꿨다.
- 읽기 화면 본문 아래에 `숫자도 설명을 위해 만든 값입니다`를 명시했다.

남긴 수치: `cx-core-cpi`의 `3.1% → 2.4%` / `2.9% → 2.8%`.
헤드라인은 내리는데 근원은 제자리라는 대조가 이 글의 전부이므로 숫자가 교육적으로
필요하다. 사람 검수에서 유지 여부를 최종 판단한다.

### 오답 시뮬레이션 — 결함 하나를 찾아 고쳤다

`scripts/sim-accuracy.mjs`. 시드 고정으로 재현된다.

| 정답률 | 시작 용어 | 익숙해짐 | 익숙해지기까지 | 평균 분 | 95% 분 | 최대 밀림 |
| --- | --- | --- | --- | --- | --- | --- |
| 100% | 60 | 42 | 9.0일 | 7.8 | 8.5 | 0 |
| 90% | 56 | 38 | 9.4일 | 7.6 | 8.5 | 2 |
| 75% | 49 | 30 | 10.2일 | 7.8 | 8.5 | 4 |
| 60% | 39 | 22 | 13.5일 | 7.8 | 8.5 | 5 |
| 형태별 85/75/65/70/60 | 50 | 30 | 10.8일 | 7.8 | 8.5 | 4 |

읽는 법: **세션 시간은 정답률과 거의 무관하다.** 개수가 아니라 시간 예산으로 뽑기
때문이다. 대신 진도가 느려진다. 이건 옳은 교환이다. 틀리는 사람에게 시간을 더
요구하는 대신 덜 나아간다.

찾은 결함: 정답률 60%에서 네 번 이상 틀린 카드가 매일 되돌아와 신규 학습이 거의
멈췄다(시작 용어 37개 대 기준선 60개). 사용자 체감은 `모르는 것만 계속 나온다`다.
`relearnInterval`을 넣어 세 번째 실패부터 이틀, 다섯 번째부터 사흘을 두게 했다.
큐에서 빼지는 않는다. 어려운 카드를 숨기는 게 아니라 다른 것을 볼 자리를 남긴다.
결과: 시작 용어 37 → 39개, B유형 30일차 밀림 6 → 0개. 전부 정답 기준선은 불변.

### 서버 방어

| 항목 | 처리 |
| --- | --- |
| `/api/export` | 토큰 없으면 404. **비밀값 미설정 시 통과가 아니라 거부.** 길이 16자 미만도 거부 |
| `/api/cron-nudge` | 같은 규칙 + Vercel 크론 헤더 허용 |
| `/api/events` | learnerId 형식 검사, 이벤트 200개·본문 128KB·payload 키 20개·문자열 200자 상한, IP당 분당 30회 |
| `/api/daily-status` | learnerId 형식 검사, 구독 정보 형태 검사(https·길이), 분당 30회 |
| 비밀값 노출 | `VITE_` 접두사만 번들에 들어간다. Upstash 토큰과 VAPID private key는 서버 전용 |
| 만료 구독 | 404/410 응답이면 구독을 지운다 |
| 검색 노출 | 관리 엔드포인트에 `X-Robots-Tag: noindex` |

`/api/health`를 만들었다. 원칙은 **사용자에게는 조용히 degrade, 운영자에게는 시끄럽게
실패**다. `/api/events`는 설정이 없어도 200을 주지만, `/api/health`는 하나라도
빠지면 503과 함께 누락 목록을 준다. 파일럿 시작 전 이 응답이 200인지 확인한다.

이전 구현의 구멍: `if (secret && auth !== ...)`로 써서 **환경변수를 잊으면
`/api/export`가 그대로 열렸다.** 잊어버리는 쪽이 안전한 방향이어야 한다.

### 이벤트 중복과 스키마

`eventId`(UUID)와 `eventSchemaVersion`을 넣었다. 전송 실패 시 커서를 올리지 않고
다시 보내므로 같은 이벤트가 두 번 닿을 수 있다. 집계 때 `eventId`로 걸러낸다.
CSV에도 두 열이 나온다.

### 완료 상태 유실 → 잘못된 알림

지적한 엣지 케이스가 실제 위험이었다. 이벤트 몇 개 유실은 괜찮지만 완료 사실이
서버에 닿지 않으면 그날 저녁에 다 한 사람에게 독촉이 간다. 그래서 두 경로의 신뢰도를
다르게 뒀다.

- 이벤트: 실패하면 커서만 유지. 다음에 같이 보낸다.
- 완료 상태: 실패하면 **outbox에 남긴다.** 앱을 다시 열 때, 화면이 다시 보일 때,
  온라인으로 돌아올 때 재전송한다(`src/main.tsx`).

### 기록 지우기와 서버 상태 일치

`기록 지우기`가 이제 네 가지를 함께 한다: 알림 구독 해지 → 서버 기록 삭제 →
**익명 id 새로 발급** → 기기 데이터 삭제. 지운 시점 이전과 이후는 다른 사람으로 센다.

### 문구 정리

- 온보딩: `들어본 말은 많은데, 막상 설명하려면 헷갈린다면.`
- 추가 세션의 `지금 더 풀어도 다음 복습은 예정대로 나와요`를 **삭제**했다.
  사용자는 복습 일정이 앞당겨지는지를 애초에 궁금해하지 않는다. 내부 동작을 설명하려고
  화면에 줄을 하나 더 두지 않는다. 동작 자체는 그대로다.

## 3. 파일럿에서 판단할 것 (지금 결정하지 않는다)

- `금융문맹 되어가는 중…`을 20~30대가 재치로 받는지 불쾌하게 받는지.
- 알림을 허용한 사람과 못 하는 사람(iOS 미설치)의 재방문율을 **따로** 본다.
  하나로 묶어 알림 효과라고 해석하면 안 된다.
- 읽기 방식별(이름/원인/다음 확인) 정답률 차이.
- `sessionSource` × `questionForm` × `exposureIndex`로 본
  기본 세션과 자발적 추가 학습의 차이, 형태별 난이도, 몇 번째 노출에서 성과가 오르는지.
- 실제 정답률이 시뮬레이션의 어느 구간에 해당하는지. 60%보다 낮으면 신규 유입
  속도와 `relearnInterval`을 다시 본다.
- 권장 분량 8분이 실제 체류 시간과 맞는지.

검증할 질문은 하나다.

> 그때그때 검색하는 것보다, 이 앱으로 반복해서 다시 만나고 구분하고 읽어보는 경험이
> 실제로 금융 언어를 `아는 것 같은 말`에서 `내가 아는 말`로 바꿔주는가.

여기에 YES가 나온 뒤에 P4로 간다. 그 전에는 기능을 늘리지 않는다.
